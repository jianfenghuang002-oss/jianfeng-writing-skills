# 工作与日常文书写作 Skill

版本：1.0.1（含 V12 定点修订）

## 1. 适用范围与优先级

本 Skill 处理以下16类文书，按任务选择体裁：

1. 正式汇报
2. 工作学习总结
3. 个人述职
4. 项目复盘
5. 活动方案
6. 项目计划
7. 可行性说明
8. 会议纪要
9. 讨论记录
10. 通知
11. 安排变更
12. 请求邮件
13. 催办
14. 拒绝
15. 更正
16. 日常工作消息

先按读者需要理解、判断或采取的动作选体裁，再选组织方式。用户本次明确要求优先；其次遵循所在单位真实有效的格式、审批与保密要求；再使用本 Skill。普通周报、社团通知或工作消息不自动套用法定机关公文格式。

**正式汇报保留原版已认可的写法：**先给当前判断、状态或建议，再给直接支撑判断的关键依据，说明影响，最后交代已定行动及确需读者作出的决定。没有决策需求时不强加“请批示”；不把所有文书统一成“事实—限制—建议”。

详细体裁要求、示例和跨体裁边界见 [`references/16类体裁写作细则.md`](references/16类体裁写作细则.md)。用户要求生成、排版或导出论文文档时，另行调用 [`references/论文文档生成与排版默认规范.md`](references/论文文档生成与排版默认规范.md)；该论文格式不套用于普通汇报、邮件、简历、讲稿或项目文档。

## 2. 写作前：确定任务和材料边界

开始起草前，先从当前对话、用户文件和已确认上下文中识别以下信息；已有信息不重复询问：

- 文书用途、接收者及其需要作出的理解、判断或行动；
- 原始材料、事实来源、统计口径、时间窗口、适用对象和版本；
- 事项状态：已发生、已核实、正在进行、拟议、已批准、未批准、待确认、已完成或已验收；
- 作者本人、团队、其他部门各自的职责与权限；
- 已知依赖、相反证据、资源限制、截止时间和必须保留的原意；
- 关键材料缺失是否会改变结论或行动。

**期限与优先顺序必须分别锁定来源。** 记录原材料明确给出的回复截止时间、活动发生时间、交付时间，不得将其中一个时点推导成另一个时点；材料未给回复期限时，不擅加日期或时刻。准确区分“按报名先后”“按回复先后”“按审批顺序”等排序依据，它们不是同义表达；材料未规定优先规则时，不自行设定。若缺失的期限或排序规则会改变名额、权益或行动结果，只问一个关键问题，或明确列为待决事项。

如果缺失信息不影响准确成稿，直接按已知材料写；如果它会改变核心判断、授权、数字或读者行动，只问一个最关键的问题。不得补造姓名、日期、数据、会议决议、审批、成本、成果、文献或承诺。建议可以提出，但必须与已批准、已落实事项分开。

内部可用简短事实表记录“主张—依据—来源—状态—责任/权限—时间窗口”。该表用于核对，不抄进成稿。保留真正影响判断的限制、反例、识别条件和风险；**如果某句话的作用只是防止被质疑，而不是推进论证，就删除。**

## 3. 起草：先选本案的阅读路径，不填固定段落

### 3.1 选择组织方式

根据本案读者任务，选择时间顺序、问题链、比较、职责归组、议题归组、参与流程、依赖链或其他自然组织方式。不同体裁有不同写作合同，按参考文件执行。篇幅由材料复杂度、读者任务和必须解释的关系决定，不以固定段数、固定小标题或字数制造“完整感”。

A/B仅在确有两种不同的信息取舍、阅读路径或论证组织值得比较时使用；比较时说明各自适用条件和代价。不得为了形式强制生成A/B，也不得把换序、换近义词当作实质差异。

### 3.2 以事实关系组织正文

不要按输入字段顺序拼接通用段落。先判断本案最重要的事实关系，再写成稿：

- 哪条事实支持哪个判断；
- 哪项产物是下一项工作的真实输入；
- 哪个条件阻止了哪项行动；
- 哪个相反证据改变了结论；
- 哪个决定授权了哪项行动；
- 哪个问题需要谁在何时提供什么，才能继续。

每个段落完成一项实际工作。段落之间必须有具体内容联系：上一段留下的事实、问题、选择或依赖，应成为下一段的起点。句间承接依靠同一对象、清楚指代、比较、条件、原因或递进关系，不靠“与此同时、因此、综上”等连接词补造逻辑。若找不到具体联系，重排、补足真实推理或删除该句/段。

### 3.3 形成自然中文

一句承载一个主要推进动作，但不要把完整推理切成碎句。条件、范围、分母和责任紧贴其限制的判断。主语、动作、对象和结果清楚；同一事项称谓稳定；避免无先行词的“其、该项、上述情况”。读起来不顺时先调整信息顺序，再决定断句。

## 4. 编辑：按顺序完成五道检查

未经审查的初稿必须原样保存。编辑后的首次对外交付稿是另一版本，不得把编辑成功追溯改判为初稿正确。

### 第一道：事实与状态

逐项核对数字、分母、时间窗、对象、版本、因果强度和来源；检查“已经、全部、导致、通过、完成、将于”等状态词是否有依据。区分模拟/影子计算与真实运营结果，练习与稳定能力，测试通过与达到验收标准，口径确认与字段核对，会议提议与会议决议。

### 第二道：权限与行动

核对作者是否有权作出该承诺，会议是否明确作出该决定，责任人和期限是否真实分配。行动必须回应正文已说明的问题，并写清对象、动作、必要依据、期限或触发条件。不得扩大原任务范围；原输入只要求提交“接口测试范围”，不得擅自扩成字段、访问角色和日志清单。合理建议、常识性流程和作者推断不得写成会议已布置任务，可另列待议建议并明确非行动项。

### 第三道：时间、容量与并发可行性

对活动方案，以及项目计划、可行性说明、通知或安排变更中涉及现场活动、分批参与、场地或并发人手的内容，必须做可复核的总量核算：

- **总时长：** 将签到/准备、安全说明、每轮活动、轮次间转场/清场/设备复位、休息和收尾全部计入。按实际先后顺序求和，与已确认的场地可用窗口比较；多轮时逐轮计算。材料若规定每批结束都需复位，最后一批也单独计入；只有明确可并行时才与全场收尾重叠。
- **空间与人数：** 分别核对各区域同时在场人数、候场区容量和场地总容量。分批安排必须写明每批人数、到场时点、等待位置和轮换方式。逐区计入参与者及在场工作人员，包括签到和轮换高峰。容量是否含工作人员不清楚时标为待确认，可按计入工作人员的保守口径给出条件方案；不得把“总人数未超场地总容量”当成每个区域均合规。
- **并发岗位：** 按时段核对指导、签到、安全、急救、秩序和无障碍协助等岗位。已确认人员不得在同一时段被分配到互相冲突的岗位；拟议岗位不能当作已到位人手。
- **设备与人员配套：** 仅使用已确认可用的设备和人员，核对设备/站点数与每组人数是否匹配。
- **条件变化重算：** 场地、人数、时间、人员、设备或安全要求变化后，重新计算总时长、各区容量及岗位覆盖，不沿用旧排程。

可用时长或容量不足时，明确展示超出量及可选取舍（延长时段、减少人数、拆分场次、改期或另设候补）；不得擅自压缩必要安全步骤、虚构资源、默认获得延期批准，或把不可行方案写成已可执行安排。所需决定未作出时，正文应准确停在待决状态。

### 第四道：结构与段落

先检查全文是否完成读者任务，再逐段检查：这一段新增了什么事实或判断？它接住上一段的哪条信息？它为下一段提供什么？检查标题是否对应正文、段落是否重复、条件变化是否传导到所有受影响位置。不要让标题齐全替代正文推理。

### 第五道：句子与文体

检查句间指代、中文语序、断句、重复解释、空泛结尾和体裁错位。删掉防御性话术、泛化愿景、重复客套、作者/审稿者写作评语（如“本次纪要应将……”）。保留真实风险、必要条件和相反证据，但放在它们实际影响的判断附近。

任何会造成虚构事实、错误判断、越权承诺、关键要求遗漏、改变原题/原任务、无法独立使用或条件变化后结论失效的问题，都必须在交付前修正；若材料不足，准确停在待决状态。一般措辞偏好不要求重写已经成立的内容。

## 5. 条件变化：重建受影响部分，不做旧稿补丁

收到新事实或新条件后，先逐项标记旧条件为：已解除、仍存在、被替代、出现新限制。再核对它影响哪些事实、比较、时间、责任、资源、审批、判断和行动。重新计算或重新判断必要结果，重排受影响段落；完整重写条件变化稿，不只增加变更摘要。已解除的障碍不继续当作现状，未解除的依赖不因单一条件满足而被宣布完成。不得将后来获得的批准回写成原会议当时已批准。

## 6. 首次对外交付关口

以真实接收者视角通读全文，确认读者能回答：

1. 这份文书在处理什么事项？
2. 当前判断/状态是什么，依据在哪里？
3. 哪些事实已确认，哪些仍待核？
4. 谁需要做什么，权限与期限从何而来？
5. 哪个结果或条件才表示任务完成？
6. 条件变化后，旧结论和旧行动是否已同步更新？
7. 所有回复期限和优先顺序是否能回溯到输入；涉及排程时长、场地容量和并发岗位的计算是否成立？

任一关键问题无法从正文回答，退回编辑；不得用内部核查表、作者评语或“请结合实际”替代成稿内容。短消息可以短，长计划、多议题纪要和复杂汇报必须展开足够的事实与依赖。

## 7. 记录与质量状态

在需要实验、审计或多轮协作时，分别保存：原始输入、未经编辑初稿、每一步编辑快照、首次对外交付稿、条件变化输入及完整重写稿、独立评语。原始失败稿保留原判定，不覆盖、不改判；同一任务多个版本只计一项。

分别记录：
- **作者自审**：作者按 Skill 自检；
- **结构/机械检查**：编号、字段、格式、重复、文件完整性等；
- **独立审阅**：未参与写作或规则修改的人审读；
- **真实受众测试**：实际接收者使用并反馈。

四者不能互相替代。未做的检查记为0或未开展，不声称真人测试、独立盲审、真实系统运行或对外发送。规范冻结后用于验收的材料，不能参与该规范修订；若验收发现规范性缺陷，另存修复版并另取新材料复测，不静默修改冻结版。
