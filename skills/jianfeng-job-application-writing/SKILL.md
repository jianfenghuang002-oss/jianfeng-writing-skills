# 剑锋写作 Skill｜求职与申请材料专项

版本：1.0.2

## 1. 适用范围与优先级

本 Skill 覆盖13种体裁：**简历、求职信、求职打招呼、自我介绍、个人陈述、面试项目陈述、人物简介、事迹材料、推荐材料、普通申请、请示、情况说明、评优材料**。体裁目录不增删。称呼用户为剑锋；用户本次明确要求优先于通用规则。

执行优先级：本次任务明确要求 → 用户最新长期偏好 → 本 Skill 核心流程 → `references/` 中对应体裁与格式细则。遇到真实学校、企业、政府机关或评奖政策，必须以适用机构当前有效文件为准；合成案例和历史来源不能代替现实规则。

本 Skill 的目标是形成事实准确、自然、可直接使用的成稿，不以增加检查项、实验数量或归档层级为目标。已成立的稿件不为统一格式强行重写。

## 2. 工作流程

### 2.1 识别写作任务

先确认四件事：谁在写、谁被介绍或评价、读者是谁、读者读完后需要理解什么或作出什么决定。同步识别载体（简历、邮件、招聘平台消息、口头陈述、正式申请或组织材料）和篇幅限制。

用户已给出明确任务且材料足够时直接完成。只有缺少会改变成稿结论的关键信息时，才问一个最关键的问题；不重复询问已有信息。可用合理假设完成的次要缺口，应标明假设，不让形式性澄清拖慢任务。

### 2.2 建立事实基础

从用户提供的材料提取：身份与资格、时间、行动主体、对象、数量及口径、本人实际动作、合作对象、交接、交付物、结果、完成状态、授权/审批状态和证据来源。区分原始事实、合理推断、未来计划与编辑备注。

不得为了语句自然补出没有依据的时间状语、数量、完成状态、交接动作、合作对象、个人贡献、心理、动机、对话或评价。没有量化结果时，使用真实交付物、实际完成范围或可复核过程，不制造增长率、节省金额、影响人数或显著效果。

### 2.3 选择材料并组织全文

先识别读者真正关心的内容，再选择能够支撑该判断的材料。不要把所有素材都塞进正文，也不要按输入字段顺序机械拼接。根据体裁选择结构，不能把所有文体统一成“事实—限制—建议”或同一种段落模板。

常见论证关系包括：
- 招聘材料：岗位实际任务 → 相关经历 → 本人具体行动 → 交付或可确认结果 → 该经历为何能支持申请。
- 个人陈述：具体经历 → 当时能够确认的认识 → 申请选择 → 现有准备 → 合理的学习目标。
- 申请/请示：明确请求 → 产生请求的事实 → 已做准备 → 需要审批方决定的事项。
- 情况说明：事件与时间线 → 已核实事实 → 当前处理状态 → 尚待确认事项。
- 人物简介、事迹材料、推荐材料分别承担身份介绍、事件叙述、推荐人评价，不相互替代。

### 2.4 起草与编辑

先完成一篇连续、完整的正文，再逐句修整。每段应承担清楚的作用；句间承接由事实和推理关系完成，不靠“此外、综上、这与岗位高度匹配”等连接词堆砌。

语言要求：
- 自然、具体、符合载体；书面材料不写成社交媒体文案，口头材料不照读简历目录。
- 删除没有推进内容的防御性句子、机械自评、重复结论和给写作者的使用提示。
- 不为显得完整而补写动机、情绪、心理、对话、赞誉或外部效果。
- 不强迫每段以“这段经历让我具备……”或“如果继续追问……”收尾。
- 断句依据句法、语义和听众理解，不习惯性在主谓、动宾或紧密语意之间加逗号；也不把多个独立意思用逗号硬连。
- 成稿与审稿意见、待核项、资格判断、修改说明分开；审稿备注不得进入真实求职或申请正文。

### 2.5 最终检查与交付

**验证后补丁 v1.0.1：**
- 项目结果动词按证据层级区分：整理/提出、展示/讨论、接收/采纳、执行、验证效果；不得将较低层级扩写为较高层级。
- 系统状态只写可观察事实。页面未显示不等于系统未保存；没有日志或后台确认，不推断上传失败、数据丢失或提交无效。

交付前完成三类实质核对：
1. **事实核对**：身份、时间、数量及口径、完成状态、交接、合作对象、个人/团队贡献、授权和审批状态。
2. **文体核对**：信息是否围绕读者任务推进；简历是否便于扫读；口头材料是否容易跟上；信件是否解释申请理由；申请是否明确所需决定；情况说明是否只陈述可核事实。
3. **条件变化核对**：重要条件变化后，重新检查受影响的请求、行动、交付、数字、结论和资格。需要时从头重写全文，不能只在末尾补一句。

缺少关键事实时，向用户问一个问题，或把待补事项放在正文之外；不得自行补联系人、推荐人签名、审批权限、资格或政策条款。

## 3. 资格、事实与写作质量分开判断

特别是简历和申请材料，分别判断：
1. **客观资格**：候选人是否满足 JD 或申请规则中的硬条件；标为符合、不符合或无法判断。
2. **正文质量**：内容是否忠实、相关、清楚、结构适配，是否遗漏关键要求或混入编辑备注。
3. **缺口处理**：是否如实呈现不满足的条件，是否虚构满足、隐瞒缺口或擅自更换目标岗位。

候选人客观不满足硬条件，不自动等于写作失败。写作错误是隐瞒、虚构、擅换目标、误导表达或没有按任务要求处理缺口。是否继续申请由用户决定；Skill 不替招聘方放宽硬条件。

## 4. 事实状态用词

- 已推免/录取但尚未入学：按实际状态写“已推免录取/拟于某年入学”，不得写成“在读硕士”。
- 拟申请、计划开展：不得写成已获录取、已加入、已完成。
- 课程项目、仿真或合成案例：不得包装成企业真实业务效果。
- 原型、展示、试点、上线、采用、验证是不同状态，不可互换。
- 本人动作、团队结果、负责人决定、审批机关认定分别归属。
- 人次不等于去重人数；统计数量不自动支持转化率、增长率或因果。
- 推荐人仅审阅材料时，不写成亲自观察全部现场过程。
- 没有数字时，可写已完成的核查表、数据字典、报告、原型、清单或建议。

## 5. 体裁执行

13种体裁的用途、受众、必要事实、材料选择、结构、段落推进、句间承接、语言断句、常见问题及完整合成示例，见：
- `references/13种体裁细则与合成示例.md`
- `references/事实核对与条件变化规则.md`

输出 Word/PDF 或其他文档文件时，先按文稿体裁、接收方要求及使用载体确定版式。普通求职材料（如简历、求职信、招聘平台消息、自我介绍和面试陈述）按各自体裁与招聘方/平台要求排版；**不得仅因交付格式为 Word/PDF，就自动套用论文版式**。

仅在任务属于论文、学位论文或其他学术文稿，或用户明确要求某份非论文材料采用该套论文排版规范时，才调用：
- `references/论文文档生成与排版默认规范.md`

来源核读层级和政策适用边界见：

## 6. 记录与验收边界

未经编辑的原始草稿、材料输入、首次完整可交付稿、作者发现的问题、修订稿和条件变化稿是不同记录：
- 原始草稿：用户提供的未经编辑文本；未提供时明确记为“无”。
- 首次完整交付稿：按完整编辑流程生成的第一份可交付正文，不等于原始草稿。
- 问题记录：引用具体原句、说明问题性质和影响；没有问题时明确记“未发现阻断性问题”。
- 修订稿：保留首次表现，不覆盖首次稿，也不倒填首次通过。
- 条件变化稿：记录变化的条件版本与完整重写稿；无历史稿时如实说明，不补造。

A/B仅在两种组织方式确有不同且值得比较时使用，不强制每项四稿。不同材料、不同任务才计为新任务；同稿修订不新增计数。

历史实验均为合成材料和作者级文字审读。不得宣称真人 HR 测试、真实投递、实际机构审批、录音计时或独立盲审，除非确有相应记录。

## 7. 效率与范围控制

不为“看起来完整”而扩写，不为统一格式而重写成立内容。缺少外部业务决定时，交付准确的待决说明，不替用户作决定。政策敏感事项按适用机构当前规则核验；单个政策待核项不应阻塞其他体裁的 Skill 使用。
