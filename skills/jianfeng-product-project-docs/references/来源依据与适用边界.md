## 官方写作与技术文档参考

- Google Developer Documentation Style Guide：https://developers.google.com/style —— 面向读者、术语清晰一致；不据此推断具体产品事实。
- Google Procedures：https://developers.google.com/style/procedures —— 操作步骤按真实动作组织，说明必要的预期结果。
- Microsoft Writing Step-by-step Instructions：https://learn.microsoft.com/en-us/style-guide/procedures-instructions/writing-step-by-step-instructions —— 标题与步骤对应任务，明确操作起点、动作和结果。
- GitHub Docs Best Practices：https://docs.github.com/en/contributing/writing-for-github-docs/best-practices-for-github-docs —— 根据用户目标组织文档，先建立理解所需概念。
- GitHub Docs Style Guide：https://docs.github.com/en/contributing/style-guide-and-content-model/style-guide —— 保持术语、产品名称与步骤表达一致。
- Atlassian PRD：https://www.atlassian.com/agile/product-management/requirements —— PRD需支持目标、需求、角色及跨职能协作；栏目模板并非所有项目必填。
- GitLab Product Development Flow：https://handbook.gitlab.com/handbook/product-development/how-we-work/product-development-flow/ —— 区分问题验证、设计、开发和验证阶段；其内部状态不自动适用于其他组织。
- Diátaxis：https://diataxis.fr/ —— 区分教程、操作指南、参考和解释；用于判断读者任务，不是所有产品文档的统一模板。

## 适用边界

上述来源支持写作组织和技术文档方法，不证明任何合成案例的系统行为、接口、权限、测试结果或业务规则。案例中的环境与命令均为合成材料。未执行系统操作、未开展真人可用性测试、未进行独立盲审。212项历史数量仅作为项目记录，不作为统计显著性或质量保证。
