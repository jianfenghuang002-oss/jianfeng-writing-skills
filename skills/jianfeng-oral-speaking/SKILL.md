# 演讲与口头汇报 Skill

版本：1.3.0

## 1. 职责与适用范围

本 Skill 负责**可以在现场自然说出来的稿件**，以及已有 PPT 的口头讲稿转换。它不负责把书面报告、会议纪要、论文正文改成演讲腔；遇到这些任务，转用对应写作规范。

先按现场任务判断主文体，而不是看标题：

- 把亲历过程讲给后来者听：S01 经验分享。
- 围绕公共议题解释问题、形成判断并倡议行动：S02 主题宣讲。
- 在会议或研讨中提出观察、分歧和问题：S03 交流发言。
- 向老师同学讲清一个概念、案例、方法或课程成果：S04 课程展示。
- 已有 PPT，需要按原页序转换成口头表达：S05 PPT 转讲稿。S05 是跨体裁处理层，仍须先选定 S01—S04、S06—S08 中的主文体。
- 讲解已经实际阅读并核对的论文：S06 文献汇报。
- 向导师和组员报告近期研究进展、障碍和讨论请求：S07 组会口头汇报。
- 向评委说明项目/研究并接受质询：S08 项目及学术答辩。

若同时符合多类，确定一个主文体，其他只作为辅助处理。不要把每种结构拼成一篇“万能汇报稿”。特别是：经验分享不必结论先行；交流发言不应变成正式汇报；课程展示不是论文答辩的缩写；研究设计答辩不能假装已有结果。

## 2. 从材料到讲稿的核心流程

### 2.1 确认现场任务

动笔前确认以下信息；材料已足够时直接写，不为凑齐清单而追问：

1. **谁在听**：其专业程度、对主题的熟悉程度、与发言人的关系，以及他们最需要听懂的事。
2. **听完要留下什么**：一个经验、一项判断、一个可执行动作、对研究结果的准确理解，或一个待讨论的问题。长稿可有少量支撑点，但应有清楚中心。
3. **谁在说、负责什么**：发言人身份、个人职责、团队分工；只写材料支持的内容。主持人已介绍或封面已有身份时，不重复念履历。
4. **事实和证据**：事件顺序、数据口径、论文原文、PPT 页面、图表、实际观察、已完成工作。区分事实、解释、假设、计划、请求和未决事项。
5. **时间与媒介**：目标时长、现场/线上、是否看 PPT、是否留问答。目标时长需要实际朗读才能确认；字数只能粗排，不能冒充计时。
6. **禁区与权限**：哪些数字、经历、结论、审批或承诺不能扩写；发言人是否有权代表团队、组织或管理方作决定。

缺少一项会实质改变稿件的关键信息时，一次只问一个最重要的问题。若可以先写而不虚构，就把未知事项准确保留为待确认，不让单个未决业务规则阻塞整篇。

### 2.2 先选推进路线，不套固定模板

写前用一句话确定：这篇稿希望听众从哪里进入，沿什么关系理解，最后能带走什么。可用时间推进、问题解决、对照、因果、证据递进、概念—例子、操作—结果等路线；只采用材料真正支持的关系。

每段要承担清楚的听觉任务。上一段留下的具体问题、结果、证据或共同关切，应能引出下一段。删掉“接下来”“下面介绍”后，段落仍应有内容联系；若没有联系，重新安排材料或明确指出缺口，不靠连接词制造逻辑。

一段通常围绕一个主要动作展开，但不必切成许多单句段。允许铺垫、回环、停顿和适量重复，只要它们帮助听众理解或形成情绪，不要把整篇压成标题串，也不要把书面段落原样照念。

### 2.3 写成可听懂的口语

- 第一次出现陌生术语，先交代当前情境，再解释它具体指什么、为什么此处需要它；后文保持译名和指代一致。
- 数字先说明对象、单位、时间范围、分母和比较基线，再读一两个真正改变判断的数。小样本优先读原始人数，不用百分比制造精确感。
- 公式先说变量、单位、适用条件，再演算一个例子。外文缩写和数学符号给自然读法或功能解释，不让听众现场听一串符号。
- 图表先引导听众看哪一组、哪条线或哪一列，再讲比较结果和能支持的判断；不要逐项念表格。
- 长句按意思组织呼吸点。发现代词指向不明、主语频繁切换、动作和对象被逗号拆开时，重组句群，而不是只换一个词。
- 自然口语不等于未经整理的口头流水账。适量称呼、追问和重复可以保留；不逐句添加“我觉得”，也不强行使用网络词、金句或排比。

### 2.4 事实、结果和权限边界

全文严格区分：

- **已经完成**：有实际记录或可复核产物。
- **已经观察**：观察发生，但不自动证明原因或普遍规律。
- **作者/团队解释**：对现象的解释，应与原始结果区分。
- **仍不能判断**：证据、样本、口径或权限不足。
- **计划/建议**：尚未执行的后续动作。
- **待批准/待确认**：需有权限的人作决定。

不得把意向写成完成、原型写成上线、模拟写成部署、准备实验写成实验完成、相关写成因果、建议写成决议、收到反馈写成全体认可。个人贡献与团队成果分开；没有来源的心理、对话、掌声、用户反应和后续行动不补造。

数字或条件改变后，重新核对所有受影响的比较、结论、建议、角色和下一步。若变化使原结论翻转，直接撤回旧判断并按新事实完整重写；不在讲稿里解释“与上一版不同”或展示改稿过程。

### 2.5 开头、身份、结尾与篇幅

开头从听众能识别的真实问题、场景、冲突或研究问题进入；正式会议可以直接说明汇报事项，不为抓眼球讲无关故事。身份介绍放在第一次需要听众识别发言资格或分工的位置。结尾从前文自然形成：经验分享可留情绪余韵；宣讲落到具体行动；交流发言留下可回应的问题；课程展示收束到可复述的知识；研究汇报说明证据强度和下一步；答辩回应评委关切。不要在结尾突然新增一组口号、未讲过的结论或无关祝愿。

压缩时优先删无关头衔、重复数据、同功能故事和枝节；保留理解主题所需的定义、关键推理、基线、单位、样本属性、约束、个人贡献和结论范围。材料不足时说明缺什么、它阻止判断什么；不得靠空话扩写。有目标时长时，按可口播正文拆分段落并给出时间预算。估算注明字数口径、语速和停顿，数字和算式按口播考虑。只有实际朗读计时，才记录为实测；明显偏短时补充听众理解所需的解释。

## 3. 八类体裁专用规则

### S01 经验分享

听众通常想知道：你当时面对什么问题、具体做了什么、为什么这样做、结果怎样、哪些经验可以借鉴。可按“起初想法—具体阻碍—行动调整—观察到的变化—适用范围与听众可尝试的一步”展开，也可从一个误区或反例切入；不要求每篇按时间线讲完全部经历。

优先选择能解释中心问题的一到两段经历。每次行动要与后续变化有事实联系，不能把履历、奖项或活动清单当成经验。失败、中断、负向结果也可以讲，不强行升华成“失败也是成功”；建议要与讲者实际经验和听众处境相匹配，不把个人路径说成普遍定律。

讲数字时说明样本、时间和分母；意向不等于参与，参与不等于完成，完成不等于满意或长期有效。个人感受可以写，但不能为情绪效果补造当时心理、对话或他人反应。结尾可回到开头的动作、问题或触动。

### S02 主题宣讲

目标是让不同熟悉程度的听众理解一个具体议题，形成有依据的判断，并知道可以做什么。可从可见现象、公共疑问或具体对比进入，再解释机制、关联和行动；不必一律热血开场，也不强制先讲故事。

证据必须说明观察对象、时间、范围和统计口径。小样本只支持该样本范围内的判断；标记数不等于确认数，预约数不等于到场数，报修数不等于修复数，个案不等于群体发生率。不能凭观察猜测行为原因或事故风险。

倡议动作要回应已知问题并符合发言人权限。志愿者不能代替管理人员批准场地、改设施或承诺资源；涉及专业安全、医疗或应急处置时，只倡议遵守场所规范、联系责任人员或专业服务，不擅自教未经授权的处置。结尾落到听众可执行的一步。

### S03 交流发言

这是平等讨论，不是替会议作决定。可接住已提供的前序发言，也可直接提出自己的观察；没有前序材料时，不编造“刚才某某指出”。常见推进是“观察到什么—可能意味着什么—还缺什么—希望共同讨论哪一项”。

明确区分事实、个人判断、建议、待确认事项和正式决议。指出可供讨论的约束与取舍，避免替管理者或会议主持人宣布场地、排期、阈值、预算或方案已获批准。结尾留下一个与会者能够回答的问题、一个需要确认的责任主体或下一步；不要机械收在“欢迎批评指正”。

### S04 课程展示

课程展示的目标是让老师和同学理解并能复述一个概念、案例、操作、方法或小组成果，不是把论文答辩章节缩短。先判断听众已掌握什么，再选择“问题—概念—例子”“现象—证据—解释”“操作—可见输出—下一步”或其他适合材料的路线。

- **概念解释**：从一个熟悉的选择或易混淆判断进入，用有边界的例子解释概念；例子必须准确体现定义。
- **案例分析**：说明数据单位、样本和比较对象；观察到的变化不自动证明原因。结尾说材料支持哪一层判断、还缺什么证据。
- **方法/代码演示**：按“输入与目标—一次操作—屏幕可见输出—该输出的意义—下一步操作”讲。首次出现SQL、Excel或统计术语时结合当前任务解释；没有真实运行或结果截图，不声称运行成功。
- **小组成果**：讲清使用动作和功能之间的关系；区分个人职责、团队成果、模拟交互、原型试用、外部验证和生产上线。
- **限时展示**：保留问题与条件、一个必要比较、可成立的结论；不删硬约束、单位、基线或结果边界。

若有公式，先解释变量、单位、分母或约束，再演算一例，并说明指标回答什么问题。页面编号、任务说明、写作提示和“本页的作用是……”等工作台标签不应混入发言正文。

### S05 PPT 转讲稿（跨体裁处理层）

只有收到真实PPT、页面截图或完整逐页文字材料，才能声称已逐页核对。材料不足时说明缺少哪些页或图表信息；可以先写已提供页面，不虚构未见页面。逐页保留用户指定页序，未经授权不擅自重排。

写前梳理每页：页面要传达的主张、听众理解它所需的前提、图表口径、上一页留下的问题、本页怎样回应、下一页为何必要。每页只讲听众判断真正需要的内容，不逐字读标题或图例。图表口播先指明视线位置，再说明行列/坐标/分母/单位，读关键关系，最后说它能支持什么。

逐页讲稿要能脱离PPT被听懂，但不重复页面上所有数字。页面间通过真实证据或任务关系连接；如果页面本身不连贯，指出缺口或给出调整建议，不编造因果填缝。身份介绍紧邻身份页；页码、舞台提示和讲者提示按用户要求放在正文外或以清晰标记呈现，不让发言人念出。

条件变化时按原页序输出完整的新讲稿，并检查所有后续数字、图表、结论和建议是否联动。真实PPT与合成逐页材料须明确区分；只有实际查看页面并进行视觉核对，才能称为“实页核对”。

### S06 文献汇报

以已读且核对过的论文原文为依据。材料至少应能确认论文身份与来源、研究问题、方法、数据/对象、比较基线、主要结果和局限。没有论文全文时，不按摘要臆写推导、实验细节或作者未报告的结论；只有合成研究简报时，明确把它当作结构练习，不称为真实文献。

从论文要解决的问题及挑战进入，再解释方法为何这样设计、关键概念如何工作、实验怎样检验、结果支持什么、适用范围在哪里。方法说明必须足以让听众理解其作用，不只是念名词。比较数字说明数据集、指标方向、基线、样本和实验条件；MAE更低不自动意味着决策成本更低，平均值不代表每个实例达标，仿真不等于真实部署。

清楚区分“论文作者报告”“汇报者的解释”“尚待核实的疑问”。结尾回到本次阅读的判断：哪项机制值得复现、哪一结论目前无法判断、下一步应核对什么。不同论文可采用不同组织路线，不逐篇机械念摘要。

### S07 组会口头汇报

服务导师和组员快速判断研究推进到哪里、证据支持什么、卡点是什么、希望得到何种反馈。依据真实的上次讨论（若有）、本周实际尝试、数据/代码/实验版本、可复核结果和待解决问题组织；没有上次决定就不编。

明确区分已经完成、已观察但未解释、未获得数据、尚未运行、结果不支持假设、计算超时、求解不可行、权限待批、口径待定等状态。它们不是同一种“遇到问题”。图表先说明样本、基线、指标和比较条件，再解释结果强度；一次划分不说成稳健结论。

让卡点自然引出下一步：哪项证据或决定阻止继续、可选动作分别改变什么、希望导师确认哪一项。讨论请求要具体可回答；不必每次都请导师“指导”。若无需批准，可提出下一步自查动作。不要套用固定“本周做了—遇到问题—下周努力”三段式。

### S08 项目及学术答辩

先分清研究设计/开题、已有结果、负向结果、中期项目、课程/项目成果等答辩类型。评委要判断研究问题与方法是否对应、比较是否公平、约束是否可行、结果是否支持结论、个人贡献是否有事实依据。没有结果的设计答辩只讲拟如何验证；未完成项目不包装成完整成果。

可选问题驱动路线（场景与问题—现有办法缺口—方法与条件—验证设计—已有证据—结论范围），也可选证据驱动路线（关键结果/反例—比较条件—方法机制—限制—个人贡献与下一步）。只在材料支持时采用。答辩必须正面回答可检验的质疑，不能只把章节标题改成问句。

结果口播说明基线、样本、单位、指标方向、成本构成与硬约束。总成本变化不等于成本参数变化；分项变化与总量可能方向不同。说明本人具体承担的工作，不把团队成果全归本人。区分可运行原型、内部测试、外部用户验证、正式部署。条件变化后重新计算并更新结论；如新条件使原判断失效，应明确撤回。

答辩追问可另列，不替代正文论证。结尾回应已回答的问题与尚需何种证据，不在结尾加入未展示的新成果。

## 4. 交付与自检

默认交付用户要求的完整讲稿；如需要PPT页码标记、停顿、操作提示或问答备忘，按要求分开标注。写作检查清单、A/B比较理由、合成材料说明、修改记录和待决事项放在讲稿之外，不让发言人念出来。

完成前至少检查：

1. 体裁是否按现场任务选对，是否误用其他文体的固定结构。
2. 讲者身份、个人贡献、事件时间、数据、样本、单位、分母和状态是否有依据。
3. 术语第一次出现时是否能听懂；公式与计算是否正确；结论是否超过证据。
4. 每段和每页之间是否有真实内容联系；删掉空连接词后是否仍然成立。
5. 是否存在模板填充、连续短句、重复免责声明、无关头衔、突然拔高或口号式结尾。
6. 条件变化后，旧事实、旧数字、旧结论是否已全部更新；新稿能否脱离旧稿独立讲述。
7. 时长是否实际计时；若没有，是否只作粗估而未宣称达标。

**A/B仅在值得比较时使用。** 只有存在两种确实不同、且都能独立上台的组织路线时才写A/B。若同一种结构更合适，不强制制造第二稿。编辑后保留首次稿、修订稿和理由；条件变化稿必须完整重写，不能只给修改说明。

- 用户明确要求生成、编辑或排版论文文档时，读取并应用 `references/论文文档生成与排版默认规范.md`。该规范不自动套用于普通讲稿、邮件、简历或产品文档。
- 最终验证材料和历史证据边界见 `validation/`；这些记录不是运行时模板，不应照搬进用户成稿。
- 条件更正改变答辩结论时，可参考 `references/答辩成本反转与试讲示例.md`，核对计算、证据范围、分工和试讲预算。
